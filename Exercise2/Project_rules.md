6. React 19 and Rules of Data Management
- use StrictMode and createRoot from react-dom/client
- Write functional components, using TypeScript for props and data.
- Don't use ReactDOM.render, class components, defaultProps, keyCode, window.alert, dangerouslySetInnerHTML, or direct DOM manipulation instead of state.
- Update the list using a functional updater, e.g. setPeople(prev => prev.filter(...)); Do not mutate state or props.
- Separate source data from filtered/sorted data clearly.
- compute visiblePeople in render with people.filter(...).toSorted(...) and don't also store visiblePeople/`filteredPeople` in useState.
- Don't use useEffect for filtering or sorting. Don't use useMemo without evidence of optimization necessity.
- Search must trim() and compare case-insensitively; handle empty string.
- Minimum IQ should always be a number. Define a stable fallback policy for invalid numeric input (the slide example uses 0).
- IQ and age sorting must have explicit, stable/deterministic tie-breaking criteria. Do not call .sort() directly on state.
Delete by stable id Reset must predictably restore the original data Don't change behavior silently. Explain separately whether Reset resets the filters or not when the design requires a decision.
